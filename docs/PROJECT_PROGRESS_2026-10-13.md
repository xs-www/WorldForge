# WorldForge 项目进展报告

> 报告日期：2026-10-13  
> 最新核查：2026-10-15（M2A.1 W99 全量规则推演）
> 核查范围：仓库文档、静态函数文档、项目配置、自动化检查与 Git 状态  
> 用途：为 WorldForge 2.0 规划提供当前实现基线，不构成新世界观 canon 或已批准的技术 ADR

## 1. 结论

WorldForge 已从“Git 管理的内容设计仓库”发展为一个可运行的、本地优先的世界观与卡牌创作工作台。当前产品已具备结构化资料编辑、SQLite 持久化、AI 候选生成、卡面图像生成、地理树、编年史和卡牌与设定关联。它不再是纯文档原型，也尚未是 WorldForge 2.0 设想中的可计算世界模拟平台。

当前最合理的开发路线是在现有产品上增量建立“定义包编译 → 世界实例 → 规则推进 → 事件与快照”的最小纵切链路，而不是立即将前端、服务端和数据库全部重写。

## 2. 当前产品形态

### 2.1 已实现的核心能力

| 领域 | 当前状态 | 实际形态 |
|---|---|---|
| 世界观编辑 | 已实现 | 13 类资料，包含世界、世界地图、势力、角色、种族、文化、宗教、魔法、科技、物品、事件、编年史和背景故事 |

| 编年史 | 已实现内容树 | 编年史容器与节点分离，支持虚构纪年文本、独立排序值、父级校验和搜索保留容器 |

### 2.2 当前技术架构

```text
无构建依赖单页前端 dist/
        │
        ├─ 内容、设置、AI 与图像 HTTP API
        │
零第三方运行时依赖的 Node 22 服务 server.mjs
        │
        ├─ SQLite 内容快照与美术资产
        ├─ LLM Responses / 兼容 Chat Completions 代理
        └─ Seedream / ComfyUI 图像通道
```

现有实现是一个适合单机作者的模块化单体。内容数据通过 SQLite 整体快照读写，而不是面向世界模拟的事件源状态库。现有“编年史”是作者编辑的设定资料，不是模拟引擎产生的权威事件日志。

## 3. 已验证状态

2026-10-15 在当前工作区执行 `npm run check`，结果为：

- 服务端与前端核心脚本语法检查通过。
- 50 项 Node 自动化测试全部通过，0 失败。
- 覆盖 AI 上下文与 Schema、卡牌兼容、编年史、地理树、提示词设置、SQLite 持久化与前向迁移、子路径路由、两种图像通道 mock、定义编译与实例化，以及确定性 Tick、资源冲突、知识隔离、快照和事件重放。

本次核查没有调用真实 LLM、Seedream 或 ComfyUI，因此不将 mock 测试解释为外部服务已完成端到端验收。Docker 已使用现有持久卷重建并进入 `healthy`；容器内 W99 从 Tick 0 自动运行至 Tick 7，能源保持守恒且历史重放一致。

## 4. 尚未实现的 2.0 能力

| 2.0 能力 | 当前进展 | 主要缺口 |
|---|---|---|
| 定义包编译 | M0B 最小实现 | 已有 JSON 清单、关键约束校验、版本化包和确定性哈希；尚无 Markdown/YAML 自动同步和完整第三方 JSON Schema 引擎 |
| 世界实例 | M2A.1 固定实验实例 | 已有 `instanceId`、定义包嵌入、随机种子、读取和事务重置；尚无通用创建、分支、归档与多实例管理 |
| 世界时钟 | M2A.1 有界连续推进 | 观察台支持手动单步和最多 50 Tick 的同步自动运行；长任务队列、取消、速度控制与后台调度尚未实现 |
| 规则/数值引擎 | M1 单资源纵切 | 支持整数能源转移与守恒；人口、价格、战争、科技和多资源尚未实现 |
| 模拟机制注册系统 | M1 契约加固已完成 | 已有版本锁定、冻结上下文、三种 Action、Effect 候选、资源读写集、知识权限和统一 Resolver；复杂动态能力令牌待实际需求出现后再设计 |
| Action Validator / Resolver | M1 契约加固已完成 | 通用 Action/Effect Schema 在业务校验和状态提交前执行；未知类型、额外参数、越权写入默认拒绝，确定性冲突仍按 seed 解决 |
| 事件日志与快照 | M2A.1 自动验收 | 接受/拒绝行动和事件流可在观察台查看；全量运行结束会自动从 Tick 0 重放并校验哈希，分支和快照压缩未实现 |
| 多尺度模拟 | 未实现 | 尚无层级精度、按需实例化、回聚和预算分配 |
| 角色认知/权限过滤 | M1 核心已实现 | 主体 KnowledgeRecord/View、来源、置信度、保密级别和过期已实现；外部 API 与复杂共享网络未实现 |
| LLM 模拟预算调度 | 未实现 | 现有 AI 配置不包含按任务能力的模型路由、多层配额、本地/云端数据策略和降级记账 |
| 世界观察器/历史实验室 | M2A 实验面板 | 已显示 W99 资源、主体视野、行动审计和事件流；尚无地图、趋势图、因果图、快照对比和分支曲线 |
| 通用外部 World API | M2A.1 W99 实验接口 | 已有单实例读取、受控 Action 推进、有界自动运行和重置；尚无认证、通用实例生命周期、观察协议和事件订阅 |

## 6. 当前主要风险

### 6.1 Git 基线已建立

项目在开始 W0/M0 开发前已审查待提交文件与忽略规则，并通过 `init` 首次提交建立可追溯基线。`.data/`、`.env.local`、本机 SQLite 数据库和密钥未进入提交。后续 2.0 实验应以该基线进行差异审查、回滚与里程碑标记。

### 6.2 内容真值、创作运行时与模拟状态易被混淆

仓库 Markdown/YAML、SQLite 中的作者草案和世界实例状态是三种不同数据。M0A/M0B 已通过 ADR-0008/0009/0010 定义发布、编译和迁移边界，并由编译测试确认默认排除 `proposed`；剩余风险是 Markdown/YAML 到编译 JSON 的人工投影尚无自动差异审核。

### 6.3 过早技术栈迁移

现有产品在零第三方运行时依赖下已经实现核心创作流程。如果在验证世界实例和规则推进之前立即迁移 React、NestJS、Prisma 和 PostgreSQL，成本主要会用于重建已有功能，而不是验证 2.0 的核心风险。

### 6.4 现有内容快照 API 不适合直接承载模拟

现有 `PUT /api/content` 使用整体快照与 revision 冲突保护，适合单作者编辑。模拟状态需要按行动、事件和 Tick 事务化提交，不应复用整体内容快照写入语义。

## 7. 建议的下一阶段

1. **接入 LLM 提案但不授予写权限**：复用现有结构化输出经验，让模型只读取 KnowledgeView 并返回待 Validator 审核的 Action。
2. **实现预算与数据策略**：为实例、区域、任务和全局建立配额，验证 `local_only` 不会回退到云端。
3. **扩展知识传播测试**：加入公开广播、受限共享、欺骗和过期情报，但不从目标真值反补历史视野。
4. **以实测数据决定迁移**：先测量多 Tick、快照体积和 SQLite 写入成本，再决定增量快照、PostgreSQL 或 Worker 架构。

## 8. 需要作者裁定的事项

以下决定会影响方向，本报告不替作者做决定：

1. WorldForge 2.0 是否优先于 W01 社会框架和卡牌对战规则，还是与早期内容里程碑并行。
2. 首个模拟原型是使用 W01 的魔导能源危机，还是使用一个与正史完全隔离的合成测试世界。
3. 外部客户端接口在首个可运行模拟前是否有硬性需求；如无，建议延后到核心事件语义稳定。

## 9. 评估边界

- 本报告的“已实现”表示仓库中存在对应实现与文档，并且相关自动化检查在本次运行中通过；它不表示已完成多人、高并发或生产级验收。
- 图像生成外部调用依赖作者配置与当地服务；本次只确认 mock 测试。
- 基础对战规则尚未确认，不应将卡牌编辑能力误读为已有可执行卡牌引擎或已完成平衡。
