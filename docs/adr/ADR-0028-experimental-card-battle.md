# ADR-0028：以 W97 合成套牌建立实验对战纵切

- 状态：canon（技术边界）
- 日期：2026-10-16
- 决策者：作者
- 来源：作者批准简单卡牌对战器与受控关键词方案

## 背景

现有卡牌编辑器能保存类型、数值、关键词引用与展示文案，但关键词尚无可执行语义，基础对战规则也未定稿。如果直接解析自由文本或执行用户脚本，无法稳定验证目标、时序与边界案例。

## 候选方案与代价

### A. 先定稿全部正式规则

- 优点：实验与最终产品偏差较小。
- 代价：会把大量未决事项绑在一起，无法快速验证对战闭环。

### B. 用纯文本解析卡牌效果

- 优点：现有草案看似可直接使用。
- 代价：自由文本存在歧义，不能作为可重现的权威规则。

### C. 内置合成套牌与白名单规则模块（采用）

- 优点：可单测、可重现，不会误读现有草案或改变正史。
- 代价：首版只支持少量效果原语，暂不能直接用作完整构筑环境。

## 决策

1. 新增 W97 合成测试卡；它们只存在于浏览器规则模块，不属于 W01 正史或作者卡牌库。
2. 实验对战使用 20 生命、10 张测试套牌、3 张起始手牌、逐回合增长且上限 10 的资源和 5 个随从栏位。这些均为 `experimental / untested`，不代表正式规则已获批准。
3. 规则引擎接受结构化命令，按权限、目标、伤害替换、事件执行、死亡与触发队列、胜负检查的稳定次序结算。
4. 关键词 `KEY-001` 疾启、`KEY-002` 护持、`KEY-003` 隔绝、`KEY-004` 余响均为 `proposed / experimental`；它们分别覆盖权限、目标约束、替换和触发四类语义。
5. `keywordUsages[].detail` 仍只是展示文字。可执行参数必须经关键词注册表和效果白名单校验；未知关键词、未知操作和任意 JavaScript 均不执行。
6. 首版规则对手只按确定性顺序出牌和攻击，不声称具备策略智能或平衡性。
7. 对战状态仅在页面内存中存活；重新开始使用固定种子重建相同初始状态，不写入 SQLite、卡牌库或世界模拟库。

## 影响范围

- `dist/battle.js`：纯规则引擎、关键词注册表、W97 测试套牌与规则对手。
- `dist/battle-ui.js`、`dist/index.html`、`dist/styles.css`：对战操作与视觉界面。
- `tests/card-battle.test.mjs`：确定性、四类关键词、默认拒绝和对手回合测试。

## 未解决问题

- 正式的费用、卡组、起手、场位、先后手补偿和胜负规则仍待作者裁定。
- 暂不支持武器、玩家组牌、手牌目标选择、持续效果、随机池和分支回放。
- 编辑器里的本地关键词仍只用于展示；尚未开放可执行行为配置。
