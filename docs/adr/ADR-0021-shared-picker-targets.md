# ADR-0021：选择窗口复用于卡牌设定来源与自由创作参考资料

- 状态：canon（技术边界）
- 日期：2026-10-15
- 决策者：作者
- 来源：作者要求把关联资料的选择窗口同样用于卡牌「设定来源」与自由创作的参考资料

## 背景

ADR-0020 把「关联资料」从多选下拉改成了可过滤的分栏选择窗口，但实现是围绕单一目标写死的：选择状态、已选区容器与按钮都直接指向关联资料。与此同时：

- 卡牌编辑器的「设定来源」仍是 `<select multiple size="5">`，把所有世界、所有类型的条目一次性铺开，没有搜索也没有筛选；卡牌的 `loreRefs`、参考图画作池与生图上下文都依赖它。
- 自由创作的「参考资料」此前只有一个复选框（附带全部条目索引）加一个自由文本框，无法指定具体条目。

ADR-0020 的未解决问题里明确记着「卡牌设定来源是否复用同一选择窗口」。

## 决策

1. 选择窗口改为按目标驱动：新增 `pickerTargets` 注册表，每个目标声明标题、排除规则、读写选择状态的函数、已选区容器、按钮、按钮文案、空状态与提交后的副作用。
2. 三个目标：`lore`（关联资料，排除当前正在编辑的条目）、`card`（卡牌设定来源，不排除任何条目，提交后刷新参考图画作池）、`free`（自由创作参考资料，不排除任何条目）。
3. 同一时刻只有一个窗口实例，打开时按目标改写标题与眉标；草稿仍只属于当前目标，切换目标不会串档。
4. 卡牌「设定来源」不再使用多选下拉，改为已选标签加「选择设定来源（N）」按钮；`selectedCardLoreRefs()` 改为读取状态数组而不是读下拉框的 `selectedOptions`。
5. 自由创作新增「参考资料」已选区与选择入口。发送时：若已选条目，把 `library` 收窄为这些条目并自动附带索引（即使复选框未勾选）；若未选，维持原行为——由复选框决定是否附带全部条目索引。
6. 三处的失效引用都按「N 条已失效引用」提示，不静默丢弃。
7. 服务端契约不变：`/api/ai/free` 原本就接收客户端传来的 `library` 数组并在服务端裁剪成索引，本次只是把数组收窄。

## 边界

- 不改变 `relationIds` / `loreRefs` 的存储格式与导出结构。
- 自由创作的参考资料仍是「名称 + 摘要 + 状态 + 事实层次 + 世界」的索引级别，不发送条目正文；发送正文属于服务端提示契约变更，需另行决策。
- 不把该窗口用于图片来源或艺术资产选择；那是另一套资源库语义。

## 影响范围

- `dist/app.js`、`dist/index.html`
- `tests/subpath-routing.test.mjs`

## 未解决问题

- 是否为自由创作提供「附带所选条目正文」的显式选项。
- 已选关联与设定来源仍不可排序。
- 参考资料是否按世界或类型默认收窄（当前默认「当前世界」过滤器）。
