# ADR-0008：作者工作区与世界定义包的发布边界

- 状态：canon（技术边界）
- 日期：2026-10-13
- 决策者：作者
- 来源：WorldForge 2.0 M0A 第一阶段开发

## 背景

WorldForge 同时存在三种不同语义的数据：Git 中可审查的 Markdown/YAML 设定，SQLite 中可随时修改的作者工作区，以及未来用于创建世界实例的只读 World Package。如果没有显式发布边界，`proposed` 草案、故事叙述或未定规则可能被误当作模拟权威初始状态。

## 候选方案与代价

1. 直接从 SQLite 实例化：路径最短，但审核状态、版本与可重现性不可靠。
2. 只允许 Git 中的 `canon / objective` 条目：最保守，但无法携带世界内信仰、传闻和有意保留的未知信息，也不利于安全实验草案。
3. 使用显式发布清单与分层编译：可追溯且能保留事实层次，但需要编译器、清单 Schema 和人工审查流程。

## 决策

1. SQLite 作者工作区是草案与编辑会话的权威存储，不是世界模拟定义源。保存、AI 生成、卡牌联动和图像生成均不触发发布。
2. Git 中经审查的结构化内容与带版本的发布清单共同构成 World Package 编译输入。编译产物是只读且内容寻址的 JSON 包，不回写源文件。
3. 默认发布只接受 `canon` 条目。`deprecated` 条目不得进入新定义包，仅可在迁移映射中作为旧 ID 来源。
4. `proposed` 条目只能通过发布清单的显式 `experimentalIncludes` 列表加入。包必须标记 `experimental: true`，不得作为默认正式定义或反向晋升任何源条目。
5. `truth_scope` 不用于简单删除内容，而是决定编译目标：`objective` 可进入权威初始定义；`in_world_belief` 只进入信念/知识种子；`unknown` 只作为未解问题和内容元数据，不得生成可执行规则或初始数值。
6. 每个发布清单必须声明 `worldId`、`definitionVersion`、源 Git commit、条目选择策略、实验条目、机制注册表版本与编译器版本。输出保留条目 ID 和源路径，以便审计。
7. 编译前必须验证 ID 唯一性、引用完整性、状态合法性、世界边界和机制依赖。缺失引用不得静默删除或自动猜测替代条目。

## 影响范围

- M0B World Package 编译器与发布清单 Schema。
- SQLite 作者工作区、Git 内容文件与模拟实例之间的数据边界。
- 后续内容同步 UI、导出、审核和定义版本迁移。

## 后续决策与未解决问题

- 发布清单已由作者确定使用 JSON，详细契约见 [ADR-0010](ADR-0010-json-world-package-contract.md)。
- 工作台中的“提交审核”界面和 SQLite 到 Git 的差异视图尚未实现。
- 背景故事当前固定为 `proposed / unknown`，只能进入实验包的叙事元数据，不得直接影响规则。
