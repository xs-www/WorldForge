# ADR-0024：自由创作可附加素材库图片，对话按轮快照参考资料

- 状态：canon（技术边界）
- 日期：2026-10-15
- 决策者：作者
- 来源：作者要求在自由对话的用户消息下显示关联资料的简短预览，并允许添加素材库里的图片

## 背景

ADR-0023 之后 Agent 能看图，但只能由它自己决定去取（`get_art_asset`）；作者无法主动把某张图放进这一轮对话。同时自由对话的消息只有纯文本气泡，作者看不出这一轮到底带了哪些参考资料与图片进上下文。

## 决策

1. 自由对话新增「图片附件」：素材库图片以缩略图列表呈现，可搜索、可点选，单条消息最多 4 张，发送后自动清空。
2. 客户端只上传资产编号（`assets`），图片字节始终由服务端按编号读取并转成 data URL，附在**该条用户消息**上。附件与消息绑定，不是全局开关。
3. `callFreeAgent` 接受每条用户消息的 `assets` 并逐条解析；无法读取的编号写进该消息正文的括号说明，不静默丢弃。
4. 「没有可检索范围」不再走单独的一次性提示词路径，改为以 `tools: []`、`maxRounds: 1` 走同一个循环。这样只附图、不授权资料库的对话也能把图片正常发给模型。
5. 工具不可用时的降级同样走循环（`tools: []` + 一轮）并把条目索引放进系统提示；与旧实现相比，**附图在降级后依然保留**，不会因为接口不支持工具而丢失。
6. 每条用户消息在发送时快照当时的参考资料（`context`：模式、条目列表、资料库总数、可检索原画数），并在气泡下方显示：`参考资料` 标签 + 条目 chip（超过 6 条折叠为 `+N`）或「整个资料库 · N 条」，再加一个「原画 N 张」chip；有附件时另起一行显示缩略图，可点开大图。
7. 快照只存在于本地消息对象上，不随请求发回服务端；之后修改参考资料选择不会改写历史消息的预览。
8. 「清空本次自由对话」同时清空待发附件。

## 边界

- 附件只读；不能借此修改、删除或重新绑定任何资产。
- 快照是展示用的，不是审计记录：它记录作者当时的选择，不代表服务端实际采用了哪些条目（服务端仍按自己的裁剪上限处理）。
- 不实现拖拽上传、粘贴图片或本地上传附件；只用素材库中已有的资产。

## 影响范围

- `server.mjs`、`dist/app.js`、`dist/index.html`、`dist/styles.css`
- `tests/subpath-routing.test.mjs`

## 未解决问题

- 4 张上限是代码常量，未在设置界面暴露。
- 历史附件会在每一轮被重新上传（无状态 API 的固有限制），没有做去重、压缩或只保留最近若干张。
- 缩略图托盘一次最多渲染 48 项，没有分页。
