# ADR-0025：正史约束从提示词移到监督点

- 状态：canon（技术边界）
- 日期：2026-10-15
- 决策者：作者
- 来源：作者指出「不擅自补成正史」在提示词与界面里出现过多，而模型没有写工具、根本改不了条目状态

## 背景

自由创作 Agent 与模块助手都只有读取能力：Agent 的五个工具全是只读（`search_lore` / `get_lore_entry` / `list_lore` / `list_art_assets` / `get_art_asset`），模块助手只返回候选 JSON，落盘一律由作者点击保存触发，且保存结果固定是 `proposed`。

在这种前提下，「不要擅自把候选晋升为 canon」是在禁止一件**不可能发生的事**。ADR-0022 / 0023 又在既有 `FREE_AGENT_INSTRUCTIONS` 之上补了一条同样意思的说明，于是同一件事在提示词里被说了两遍、在界面里被说了四遍（AI 助手面板、卡牌设定来源说明、自由对话页脚、设置的数据管理）。约束越多，真正需要模型注意的指令相对权重越低。

## 决策

1. 删掉针对「改状态」这一不可能动作的禁令。给 Agent 的提示词不再出现「擅自」「晋升」「正史」这类措辞。
2. 保留并改写为**输出纪律**，只在自由 Agent 的系统提示里说一次：引用资料时按其 `status` 与 `truthScope` 表述，`proposed` 是草案、`unknown` 是留白，不要写成已定论，也不要补全资料本身没写的内容。这是真实存在的失效模式：模型读到草案却在正文里写得像定论，即便它什么都没改。
3. 保留「工具是只读的；你无法写入、删除」这一条。它是**能力陈述**而不是禁令，作用是让模型不要承诺自己做不到的修改。
4. 界面从四处重复收敛为一处，并且改成说明**作者该做什么**而不是重复禁令：AI 助手面板的「草案边界」改为「AI 只返回 proposed 建议；勾选并保存才会进入资料库，何时晋升 canon 由你在世界观界面决定」。其余三处只保留作者确实需要知道的行为事实（「只预填草案，需要你保存才生效」「对话不会写入资料库」「不会自动写入仓库」）。
5. 模块助手的 `SYSTEM_INSTRUCTIONS` 保留「不得修改、否定或悄悄补完 canon」。这里的重点是**不要为填补已批准设定的空白而编造内容**，属于内容质量约束，与权限无关，因此不在本次删减范围内。

## 边界

- 不改变任何权限：工具仍然只读，写路径仍然只由作者点击触发。
- 不改变正史政策本身（`canon` 只能由作者批准），只改变这条政策被陈述的位置与次数。
- 不删减原创性与 IP 边界相关的提示；它们对应的是真实且可发生的失效模式。

## 影响范围

- `ai-harness.mjs`（`FREE_AGENT_INSTRUCTIONS`）、`server.mjs`（`FREE_AGENT_TOOL_GUIDE`）、`dist/index.html`
- `tests/subpath-routing.test.mjs`

## 验证

用真实模型验证删减没有丢掉有用约束：资料库里只放一条 `status: proposed` / `truthScope: unknown` 的条目并追问其中的具体数字。模型调用 3 次工具读到正文，答出该数字，主动标注 `proposed` 与 `unknown`，区分「条目写的」与「条目自己标注为未确定的」，最后给出两个设计方向交作者选择，而不是宣称自己去改动任何内容。

## 未解决问题

- 模块助手的 `<worldforge_context>` 里仍带一份 `projectRules`（含「新增内容只能是 proposed」），与 `SYSTEM_INSTRUCTIONS` 有部分重叠；这一份是否也收敛尚未决定。
- 是否需要把「哪些约束对应真实失效模式、哪些只是防御不可能动作」写成长期的提示词审查清单。
