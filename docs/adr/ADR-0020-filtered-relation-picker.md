# ADR-0020：关联资料改用可过滤的分栏选择窗口

- 状态：canon（技术边界）
- 日期：2026-10-15
- 决策者：作者
- 来源：作者要求把「关联资料」由全量拼接的下拉框改为子窗口：上半部分为可搜索可过滤的全量资料，下半部分为已选词条

## 背景

「关联资料」原先是 `<select multiple size="4">`，把所有世界的条目一次性拼进下拉框，只有「当前世界平铺 + 其他世界一个分组」这一层结构，没有搜索、没有类型或状态过滤，也没有独立的已选区。资料增长后，找一条要关联的条目需要在一长串选项里滚动，而且选中状态在关闭下拉后不可见。

## 决策

1. 关联资料改用 `<dialog id="relationDialog">` 分栏选择窗口：一侧为全量资料池，另一侧为已选关联；窄屏改为上下堆叠。
2. 资料池支持搜索（名称、编号、摘要、正文、标签）与四个过滤器：类型（13 类 + 全部）、世界（当前世界 / 其他世界 / 全部世界，默认当前世界）、状态（canon / proposed / unknown / deprecated / 全部）、显示（全部 / 仅未选 / 仅已选）。
3. 当前正在编辑的条目永远不会出现在资料池里。
4. 选择过程在草稿集合中进行：点条目加入或移除，右侧「已选关联」实时反映。只有点「应用关联」才写回表单；「取消」或关闭窗口丢弃草稿。
5. 编辑器表单里不再有下拉框，改为已选关联的只读标签列表加「选择关联资料（N）」按钮；失效引用以「N 条已失效引用」单独标出，不静默丢弃。
6. 过滤、切换、汇总逻辑抽成纯函数模块 `dist/relation-picker.js`（`filter` / `toggle` / `remove` / `summarize` / `missingCount`），配独立 Node 测试；`app.js` 只负责渲染与状态。
7. 本决策取代 [ADR-0019](ADR-0019-world-hub-two-level-navigation.md) 决策 6 中「关联下拉按世界分组」的实现方式；「同世界优先、跨世界可选」的分层意图不变。

## 边界

- 不改变 `relationIds` 的存储格式、顺序语义或导出结构；仍然是稳定 ID 数组。
- 不引入层级、权重或关系类型等结构化关联语义；本次只改选择界面。
- 不改变背景故事、卡牌设定来源等其他多选控件的实现；卡牌「设定来源」仍是多选下拉。

## 影响范围

- `dist/relation-picker.js`（新增）、`dist/app.js`、`dist/index.html`、`dist/styles.css`
- `tests/relation-picker.test.mjs`（新增）、`tests/subpath-routing.test.mjs`
- `package.json`

## 未解决问题

- 已选关联目前不能排序，顺序等于添加顺序。
- 是否给关联引入「关系类型」（隶属、对立、衍生）仍待作者裁定。
- 卡牌「设定来源」是否复用同一选择窗口。
