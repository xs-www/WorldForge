# ADR-0027：AI 设定助手浮动化，候选可覆盖当前条目，候选数可为 1

- 状态：canon（技术边界）
- 日期：2026-10-15
- 决策者：作者
- 来源：作者要求把 AI 设定助手独立到子窗口并允许最小化回侧边栏、允许用候选覆盖当前条目、允许只生成 1 份候选

## 背景

AI 设定助手此前是资料工作区的第三列（`grid-template-columns: 260px minmax(560px,1fr) 300px`），长期占用横向空间，也无法在不看它的时候收起来。候选数量只能选 2–5，而服务端与 Schema 早已按 `Math.min(5, Math.max(1, …))` 处理，1 份本来就支持，只是界面没给选项。助手只能「保存所选为独立草案」，或用「应用到当前表单」再手动保存，缺少一步到位的覆盖动作。

## 决策

1. AI 助手改为浮动子窗口：`position: fixed` 固定在右侧，与资料工作区解耦（工作区改回两列），并保持**非模态**——写作时需要一边看编辑器一边用助手。
2. 三态：`open`（展开 368px）、`min`（最小化为 46px 竖条，点击任意处展开）、`closed`（隐藏，由右侧边缘的「AI 设定助手」竖按钮重开）。状态写入浏览器本地键 `worldforge-ui-state-v1`，不进入内容导出，也不写入 SQLite。
3. 窄屏（≤820px）改为底部抽屉：展开时占 68vh，最小化时 46px 高。
4. 候选数量新增「1 份」。服务端、JSON Schema 与补生成逻辑都已支持 1，因此只改界面选项，不改契约。
5. 非故事模式下，每张候选除「应用到当前表单」外新增「覆盖当前条目」：确认后用该候选覆盖已勾选内容块并立即保存。实现复用既有的 `applyAiVariant()` + `saveLore()`，因此仍走完整的字段校验与状态规则，不绕过它们。
6. 「覆盖当前条目」只在已保存条目（`activeLoreId`）上出现；未保存的新资料只能先用「应用到当前表单」。

## 边界

- 不改变候选的 Schema、逐条验收与补生成逻辑；只是数量下限从 2 变成 1。
- 覆盖是零可撤销性的操作，因此必须经过 `confirm()`；本条不引入版本历史或撤销栈。
- 助手仍是模块助手（结构化候选），不获得自由创作 Agent 的工具能力。
- 浮动状态是纯界面偏好，不进入统一导出与 SQLite。

## 影响范围

- `dist/app.js`、`dist/index.html`、`dist/styles.css`
- `tests/subpath-routing.test.mjs`

## 未解决问题

- 浮动窗口宽度不可拖拽调整。
- 覆盖操作没有撤销，只靠作者确认。
- 是否把浮动状态并入设置页的编辑偏好（当前用独立本地键）。
