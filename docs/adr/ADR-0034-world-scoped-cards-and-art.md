# ADR-0034：卡牌与原画按世界归属

- 状态：proposed（产品接口），待作者裁定
- 日期：2026-10-21
- 相关：ADR-0018（原画集覆盖全量素材）、ADR-0026（原画可解除绑定）、ADR-0031（多世界与资料组）、ADR-0033（设定导入）

## 背景

卡牌草案的数据层早已有 `worldId`（`card_drafts.world_id`、`WorldforgeCards.normalize`、`buildCardContext`），但三处都没有把它当契约：

1. **编辑器**：`#cardWorldId` 是自由文本输入框，默认值来自 `currentWorldId()`，没有世界时可以留空保存，于是库里出现「不属于任何世界」的卡牌；卡牌编号 `CARD-${worldId}-DRAFT-*` 在为空时退化成 `CARD--DRAFT-*`。
2. **卡牌库**：`renderCards` 不看世界，全部世界的卡牌混排；卡面无任何世界标记。
3. **原画**：`art_assets` 只存 `targetType` / `targetId`，没有世界；原画集把所有世界的画作混在一起，只有「已使用 / 未使用」两种分类。

作者指出：**不同世界的画风不一致，卡牌和原画应当归属世界**。这是内容一致性问题，不是界面偏好——同一套卡面语言横跨两个世界，会让两个世界的视觉规范互相污染。

## 决策

### 1. 卡牌必须属于一个世界

- 编辑器的「所属世界」改为下拉（`fillWorldSelect`），列出所有世界编号 + 名称；没有世界时下拉只剩占位项。
- 保存时 `if (!worldId) return showToast('请先为卡牌选择所属世界…')`，前端不再产生无世界卡牌。
- 旧数据里 `worldId` 为空的卡牌显示为「未归属」，可以打开编辑但保存前必须补选；不写迁移脚本静默指派世界——归哪个世界只能由作者决定。
- 卡牌库新增 `#cardLibraryWorld` 筛选（全部世界 / 未归属 / 具体世界），卡面左上角加 `.card-world-chip` 世界徽标，`aria-label` 与 `data-world` 同时带上世界，供测试与辅助技术读取。
- 卡牌 Agent 的草案上下文补上 `worldId`（此前服务端 `buildCardContext` 已读取 `draft.worldId`，但前端 `collectCardDraftForAgent` 从未发送，等于校验了一个恒为空的字段）。

### 2. 原画的世界由绑定目标决定，不由作者手填

- 生成时服务端按目标现算 `worldId` 并写进资产元数据：目标是卡牌 → 卡牌的世界；目标是设定条目 → 条目的世界。
- 读取时（`GET /api/art-assets`、`GET /api/export`）同样现算一次，覆盖元数据里的旧值：这样卡牌换世界、条目迁移世界后，原画归属自动跟着走，不会留下过期字段。
- 解除绑定（`POST /api/art-assets/:id/unbind`）清空 `worldId`，原画回到「未归属」，但仍留在素材库。
- 不新增数据库列：`worldId` 存在 `art_assets.metadata_json` 里，读取时以内容库为真值；这样不需要迁移，也不会出现「元数据与目标冲突」的第二种真相。
- 原画集新增 `#artworkWorld` 筛选与 `.artwork-world` 徽标；空状态文案区分「该世界暂无匹配原画」与「素材库还没有原画」。

### 3. Beta 标记

「测试对战」与「世界模拟」在导航里加 `.beta-tag`，`title` 写明「实验模块：规则数值与界面都可能调整」。它们本来就是 experimental / untested 的实验纵切（ADR-0028、ADR-0013），此前只在 README 与文档里说明，界面看不出来。

## 代价与取舍

- **卡牌必须选世界**会让「先随手记一张卡、之后再归世界」的流程多一步。接受这个代价：无世界卡牌正是要消除的形态；「设定」组式的未归属兜底对卡牌不适用，因为卡面语言必须与某个世界的视觉规范对齐。
- **原画归属随目标变化**：把卡牌改到另一个世界，它的原画也跟着换世界。这是期望行为（画作确实服务于新世界），但也意味着作者不能再让一张原画「同时属于两个世界」；跨世界复用需要复制一份。
- **跨世界引用设定只提示不阻止**：编辑器的 `#cardWorldHint` 会说明「有 N 条设定来源属于其他世界」，但仍允许保存。设定引用是叙事依据，跨世界借用有时是刻意的；强制拦截会挡住合理用法。
- **未归属卡牌不会自动迁移**：不猜作者意图，旧卡牌保持可见、可编辑、可保存（补选世界后）。

## 验证

- `tests/app-load.test.mjs`：新增「卡牌必须归属世界：没有世界拒绝保存，选了世界后写入 worldId」「卡牌库按世界筛选，并在卡面显示世界徽标」「原画跟随绑定目标的世界，并可按世界筛选」三项真实脚本 + DOM 替身测试。
- `tests/subpath-routing.test.mjs`：新增「卡牌与原画归属世界（ADR-0034）」与「测试对战与世界模拟标注 Beta（0.3.2）」两项源码契约断言（编辑器是 select、保存守卫、两个筛选控件、服务端现算函数与路由、Beta 标记与深色样式）。
- `tests/data-transfer-api.test.mjs`：新增端到端「原画跟随目标世界：列表与导出带 worldId，解除绑定后清空」——真实 `server.mjs` + 临时数据目录，验证服务端现算而不是听客户端。
- `tests/storage.test.mjs`：既有「美术资产可解绑再重绑」用例继续覆盖 `worldId` 在解绑时清空的路径。
- **未验证**：真实浏览器里世界徽标在窄屏 / 深色主题下的对比度、上千张原画时按世界筛选的性能、以及作者对「必须选世界」这一限制的实际接受度。这些需要作者实测。

## 未决问题

- 是否把「世界视觉规范」（每个世界的材质、色板、时代感）显式存进世界条目并自动拼进生图提示；当前只靠世界条目的正文与 `defaultArtPrompt` 的措辞。
- 卡牌类型（随从 / 法术 / 武器）是否也应像资料组一样按世界可配置（ADR-0031 之后资料组已按世界作用域，卡牌类型仍是产品常量）。
- 一张原画是否允许跨世界复用（复制一份 vs 允许共享）。
- 「未归属」卡牌在作者长期不处理时是否需要批量指派入口。
