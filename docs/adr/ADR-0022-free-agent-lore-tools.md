# ADR-0022：自由创作 Agent 获得多轮只读资料工具

- 状态：canon（技术边界）
- 日期：2026-10-15
- 决策者：作者
- 来源：作者要求把自由创作视为 Agent，赋予多轮 tool call 能力，允许它向 harness 请求查看某词条详细资料

## 背景

自由创作此前的调用是单轮的：服务端把「关联信息 + 资料库索引 + 对话」拼成一段提示词，请模型直接回复，返回纯文本 `reply`。作者能提供的最细粒度上下文只有「名称 + 摘要 + 状态 + 事实层次 + 世界」的索引，**无法让模型读到条目正文**；想让模型基于某条设定作答，只能把正文手动粘进关联信息。

资料库已经结构化并带稳定 ID，具备按需检索的条件；服务端又不应该把整库正文一次性塞进提示词（token 成本与注意力稀释）。

## 决策

1. 工具执行放在**服务端**（`ai-tools.mjs`），即作者所说的 harness：模型输出工具调用，服务端在随请求传入的资料库快照上执行并回填结果，全程不访问文件系统、数据库或密钥。
2. 首批三个只读工具：`search_lore`（关键词 + 类型/世界/状态过滤，返回编号、名称、状态、事实层次与摘要）、`get_lore_entry`（按稳定 ID 读取 1–5 条完整正文、约束、开放问题与关联编号）、`list_lore`（索引列表）。搜索不返回正文，迫使模型在引用内容前先精确读取。
3. 多轮循环在 `ai-agent.mjs` 中以**可注入**形式实现：`runAgentLoop({ messages, tools, callModel, runTool })`，模型调用与工具执行都由调用方提供，因此可以用脚本化假模型完整测试。
4. 预算有界：最多 6 轮、12 次工具调用。预算用尽后不再提供工具；轮次用尽则追加一条「请基于已取得资料作答」的指令强制收尾。两种停止原因都在返回值中如实标注。
5. 工具结果一律随附 `status` 与 `truthScope`；系统提示明确要求不得把 `proposed` 草案或 `unknown` 留白当作已批准正史，也不得凭摘要臆测正文。
6. 工具调用轨迹（轮次、工具名、成功与否、一句摘要）随回复返回前端，并在对话气泡下以可折叠形式展示，让作者看见 Agent 到底查了什么。
7. 作者可检索的范围由 ADR-0021 的「参考资料」选择决定：已选条目即以这些条目为范围；未选且「允许 Agent 检索整个资料库」开启时以全库为范围；两者都没有则退回无工具单轮问答。
8. 兼容性降级沿用既有模式：模型服务拒绝工具（HTTP 400 / 404 / 422）时，退回一次不带工具的问答，并把条目索引直接放进上下文，返回值以 `toolMode: 'unavailable'` 标注；其余错误照常抛出。
9. 两种 API 风格都支持工具调用：Chat Completions 使用 `tools` + `tool_calls` + `role: 'tool'`；Responses 使用 `tools` + `function_call` + `function_call_output`。线格式构造与解析为纯函数，单独测试。
10. Dockerfile 的显式文件白名单新增 `ai-tools.mjs` 与 `ai-agent.mjs`，并新增 `tests/docker-packaging.test.mjs`：从 `server.mjs` 出发解析本地模块传递闭包，逐个要求在 COPY 白名单内，防止再次出现「镜像构建成功但容器启动即模块缺失」。

## 边界

- 工具严格只读：没有写入、删除、执行或跨出资料库快照的能力；提示词中明确告知模型这一点。
- 不上传资料库以外的任何内容；工具只能看到随请求传入的条目。
- 降级路径仍然是索引级别，不含正文；这与工具路径的能力差异会被如实标注，不伪装成工具调用成功。
- 不引入向量检索、全文索引或跨世界推理；工具只在内存中的数组上做字符串匹配。

## 影响范围

- `ai-tools.mjs`、`ai-agent.mjs`（新增）、`server.mjs`、`dist/app.js`、`dist/index.html`、`dist/styles.css`
- `tests/agent-tools.test.mjs`、`tests/agent-loop.test.mjs`、`tests/docker-packaging.test.mjs`（新增）、`tests/subpath-routing.test.mjs`
- `package.json`、`Dockerfile`

## 未解决问题

- 轮次与工具次数上限目前是代码常量，未在设置界面暴露。
- 同一轮内的重复检索没有做去重或缓存（实测模型会发出命中 0 条的重复查询）。
- Agent 是否应能查看美术资产、卡牌草案或模拟状态，尚未决定。
- 工具结果的字符预算（当前单次 6000 字符、正文 8000 字符）是否需要按模型上下文窗口自适应。

## 修订

- 2026-10-15：未决项中的美术资产已由作者决定必须可见，卡牌草案与模拟状态仍不可见。图像无法放在工具结果消息里，因此新增了「工具返回资产编号 + 服务端附图 + 视觉降级」的机制，见 [ADR-0023](ADR-0023-agent-art-vision.md)。
