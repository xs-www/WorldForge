# ADR-0014：用有界规则主体跑通 W99 完整模拟闭环

- 状态：canon（技术边界）
- 日期：2026-10-15
- 决策者：作者
- 来源：作者要求优先全量跑通模拟

## 背景

M2A 已能手动推进一个 Tick，但作者仍需理解四个工程预设并自行组合，无法直接验证“主体决策 → Action → 契约与 Validator → Effect 结算 → Event/Knowledge → Snapshot → Replay”的完整链路。直接依赖 LLM 会让模型配置、网络、预算和生成质量成为闭环可用性的前置条件。

## 候选方案与代价

### A. 立即只接 LLM 自动决策

- 优点：行为表达更丰富。
- 代价：无模型 Key、超时或预算耗尽时无法跑完；难以区分规则问题与模型问题。

### B. 先用确定性规则主体跑通，再把 LLM 作为可降级提案器接入（采用）

- 优点：零外部依赖、结果可复现，可先验收完整状态链；后续 LLM 与规则主体提交相同 Action 契约。
- 代价：当前策略只覆盖 W99 能源危机，不代表通用国家或人物智能。

## 决策

1. 新增 W99 专用规则主体：供能机构在持有能源时向市政机构转交，否则申请固定配额；市政机构持有能源时消耗，否则申请固定配额。策略只使用主体身份、角色、自身余额、公开地区和目标 ID，不读取其他主体秘密余额。
2. 新增有界批量推进接口 `POST /api/simulation/run`。请求必须带当前状态版本，默认最多推进 20 Tick、硬上限 50 Tick；达到“储备为 0 且主体持有为 0”或 Tick 上限后停止。
3. 每个自动 Tick 仍逐项经过现有 Action/Effect 契约、Validator、确定性冲突排序、Resolver 和原子提交，不提供绕过规则的批量写入口。
4. 批量结束后从 Tick 0 快照重放全部已提交事件并核对权威状态哈希；重放失败视为模拟失败。
5. 新增 `POST /api/simulation/reset`，要求当前状态版本，并在单个 SQLite 事务内级联删除旧实验历史和重建同定义、同随机种子的 Tick 0 实例。
6. UI 以“一键运行完整模拟”为主入口，同时保留手动单步调试；显示储备、主体持有、累计消耗和重放验证结果。
7. 此闭环仍是 W99 experimental 验收，不晋升 W01 正史，也不宣称已经实现 LLM 区域模拟、多地区经济或通用实例生命周期。

## 验收条件

- 从初始 12 能源出发，规则主体在 20 Tick 内达到储备 0、主体持有 0、累计消耗 12。
- 能源总量全程保持 12；接受和拒绝 Action 均进入审计。
- 最终历史从 Tick 0 重放后与权威快照哈希一致。
- 重置后 Tick、Action、Event 和 Knowledge 恢复初始状态；再次运行得到相同最终状态哈希。
- 过期版本和非法 Tick 上限被拒绝；模拟不依赖 LLM、网络或付费 API。

## 影响范围

- `simulation/agents/rule-agent.mjs`、模拟存储重置事务、观察台服务及实验 API。
- 世界模拟 UI、测试、README、进展报告、TODO、Changelog 与静态函数文档。

## 未解决问题

- LLM 提案、预算调度、数据策略与实耗账本尚未接入。
- 当前只有固定 W99 实例；通用实例创建、暂停中的后台任务、分支和删除仍未实现。
- 当前批量推进同步执行且上限 50 Tick；长历史需要任务队列、取消和进度流。
