# ADR-0013：以 W99 实验 API 与观察台公开首个模拟界面

- 状态：canon（技术边界）
- 日期：2026-10-15
- 决策者：作者
- 来源：作者要求继续 WorldForge 2.0 并尽快提供 UI 显示

## 背景

M1 已有可推进、审计和重放的纯规则模拟，但只能通过模块测试观察。若先接入 LLM 再做界面，作者无法直观看到 Action 是否被接受、资源是否守恒、不同主体知道什么，也难以判断后续 Agent 行为是否可信。

因此先建立一个只服务 W99 合成场景的 M2A 可见纵切：用独立模拟数据库持久化实例，通过受限 API 读取状态和提交手动 Action 提案，并在现有单页产品中显示 Tick、资源、审计和 KnowledgeView。

## 候选方案与代价

### A. 等 LLM 模拟完成后一次性建设 UI

- 优点：减少一次界面迭代。
- 代价：核心模拟长期不可见，LLM、规则与界面问题会混在一起，验收困难。

### B. 先做 W99 观察台与手动推进（采用）

- 优点：立即获得可操作反馈；先验证 API、状态展示和主体视野，再复用同一入口接入 LLM Action 提案。
- 代价：首版只有一个实验实例和固定操作预设，不是通用世界管理器。

### C. 直接把模拟状态并入作者内容 API

- 优点：接口数量较少。
- 代价：会混淆创作资料与运行时状态，违反 ADR-0008/0009 的数据边界。

## 决策

1. 新增独立 `worldforge-simulation.sqlite`，默认与内容数据库位于同一数据目录；可用 `WORLDFORGE_SIM_DB_PATH` 覆盖。它继续使用 `sim_` 表和独立迁移账本。
2. 服务启动时确保存在固定实验实例 `INST-W99-DASHBOARD`；只实例化 W99 experimental 定义，不读取或修改 W01 canon。
3. 新增实验接口：
   - `GET /api/simulation`：返回 Tick、状态版本、定义哈希、机制 Action 契约、地区/主体资源、总能源、最近行动/事件和逐主体 KnowledgeView。
   - `POST /api/simulation/advance`：要求 `X-Worldforge-Simulation: 1`、当前状态版本和至多 10 个 Action 提案；服务器生成 Action ID/Tick，再交给现有契约、Validator、Resolver 和原子提交链路。
4. 外部请求不能直接提交 Effect、知识记录、随机样本、Action ID 或目标 Tick；这些字段由可信服务和运行时产生。
5. 单页产品新增“世界模拟”模块，显示权威资源状态、主体视野、行动审计和事件流，并提供竞争申请、主体转交、能源消耗与空 Tick 四个手动实验。
6. UI 明确标注 `experimental · W99`，不得把运行结果展示为正史或自动写回作者资料库。
7. 本阶段不调用 LLM。下一阶段的模型只能产生与手动操作相同的 Action 提案，并继续经过此 API 后方的契约和 Validator。

## 验收条件

- 初始页面显示 Tick 0、状态版本 0、总能源 12 和两个主体的空 KnowledgeView。
- 运行竞争申请后进入 Tick 1：一项接受、一项拒绝，总能源仍为 12，只有接受主体得到私有观测。
- 过期状态版本返回 409；未知主体、非 energy Action、非法参数或每 Tick 超过 10 项提案被拒绝。
- 内容数据库与模拟数据库物理分离；页面和 API 均明确 W99 非正史。
- 根路径与 `/worldforge` 子路径继续使用相对 API URL。
- 桌面页面完成真实浏览器视觉与交互验收，`npm run check` 全部通过。

## 影响范围

- `simulation/dashboard-service.mjs` 与独立模拟 SQLite 文件。
- `server.mjs` 的健康信息和两个实验 API。
- `dist/index.html`、`dist/app.js`、`dist/styles.css` 的模拟观察台。
- API、服务、静态界面测试及部署/项目文档。

## 未解决问题

- 尚无实例列表、创建、重置、暂停、分支和删除生命周期。
- 尚无登录与细粒度主体授权；当前接口只面向现有本机/tailnet 部署边界和 W99 实验。
- UI 只有资源数值、审计和知识列表，尚无地图、趋势图、因果图或快照对比。
- LLM Action 提案、预算调度、`local_only` 策略和实耗审计进入下一阶段。
