# ADR-0006：将背景故事作为独立可关联资料

- **状态**：canon
- **日期**：2026-10-13
- **范围**：HTML 产品的设定资料结构与 AI 草案流程，不改变任何世界观 canon

## 背景

作者希望不先构建完整而庞大的百科式世界，而是从人物传记、地点轶事和局部事件逐步填补世界。单个设定条目需要挂载多篇背景故事，故事之间也需要建立可追踪关系。

## 决策

1. 背景故事是第 13 类独立资料，使用稳定 ID `STORY-W##-####`；本地未定稿 ID 使用 `STORY-W01-DRAFT-*`。
2. 故事的创作内容只有标题与正文，不提供摘要、约束、开放问题、标签或类型专属属性。ID、世界、固定的 `proposed / unknown` 状态和关联只作为内部管理字段。
3. 一篇故事可以关联多个普通设定条目和多篇故事；一个人物、地点或其他条目也可以被多篇故事反向引用。
4. 界面在当前条目下展示所有反向挂载故事；打开故事时展示显式相关故事。
5. 手工新建故事内部固定为 `proposed / unknown`，但编辑器不显示这些技术状态。AI“生成背景故事”只展示标题与故事正文，作者选择后才保存，并自动关联生成时的锚点条目。
6. 故事中的叙述不自动成为 `objective canon`。若故事确定了客观事实，仍需按正史政策另行裁定。

## 取舍与边界

- 首期复用 `lore_entries` 与 `relationIds`，不新增数据库表；旧数据库无需迁移。旧故事中曾保存的摘要、约束、开放问题、标签和类型属性会在下次保存时清空。
- 关联当前为无类型引用，相关故事由资料类型与正向/反向关系计算；暂不实现关系标签、章节排序、版本分支或长篇章节管理。
- AI 自动测试只校验提示边界与结构，不调用真实模型，也不声称故事质量已经通过人工评审。
