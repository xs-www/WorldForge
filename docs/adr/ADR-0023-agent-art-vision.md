# ADR-0023：自由创作 Agent 可以查看美术资产

- 状态：canon（技术边界）
- 日期：2026-10-15
- 决策者：作者
- 来源：作者要求后续 Agent 必须能看到美术资产，因为视觉原型很重要；卡牌草案与模拟状态不需要

## 背景

ADR-0022 给自由创作 Agent 加了多轮只读资料工具，但只覆盖文本条目，并把「Agent 是否应能查看美术资产」列为未决。作者明确要求必须先做这件事。

美术资产与文本资料有一个关键差别：**它是图像**。工具调用的结果消息（Chat Completions 的 `role: 'tool'`、Responses 的 `function_call_output`）只能承载文本，图片必须作为带图的消息附到会话里，模型才真正看得到。仅返回资产的元数据（用途、尺寸、生成通道）不足以让模型判断画面内容。

## 决策

1. 新增两个只读工具：`list_art_assets`（按目标、目标类型、用途过滤，返回资产编号、用途、绑定目标、生成通道、尺寸与生成时间的索引）与 `get_art_asset`（按编号查看 1–4 张原画的实际画面）。
2. `get_art_asset` 只返回需要附图的资产编号（`imageIds`）与元数据文本；**图片本体由服务端**从资产目录读取后转成 data URL，再由循环作为紧随工具结果之后的一条用户消息附上。工具消息本身永远不带图。
3. 单轮附图上限 4 张；`get_art_asset` 一次最多请求 4 个编号。附图消息明确写出「以画面为准；与文字不符时说明差异」。
4. 视觉能力降级：模型接口拒绝图片（HTTP 400 / 404 / 422）时，把已附图的消息改写成文字说明（而不是静默丢图）、继续对话，并在返回值中标注 `vision: 'unavailable'`。其他错误照常抛出，不会被降级逻辑吞掉。
5. 返回值新增 `vision`（`ok` / `unavailable` / `none`）与 `images`（本次附图张数），工具轨迹的每条记录带 `images` 张数。前端在对话气泡下如实展示「附图 N 张」或「模型接口不接受图片，已移除附图」。
6. 客户端只上传美术资产的**元数据索引**（上限 200 条，且不含本地路径与文件字节）；图片字节始终留在服务端。
7. 可见范围沿用 ADR-0021 的授权模型：作者提供了可检索范围（选了参考资料，或开启「允许 Agent 检索整个资料库」）时，美术资产索引一并提供给 Agent；完全没有授权时不提供任何工具。不按条目逐条收窄美术资产，因为卡牌原画无法通过资料条目授权到达。
8. 卡牌草案与模拟状态**仍然不可见**，符合作者本次的边界要求。

## 边界

- 工具依旧严格只读；美术资产只能被列举与查看，不能被修改、删除或重新绑定。
- Agent 拿到的是渲染后的画面，不是工程文件、图层或原始提示词之外的元数据；`get_art_asset` 可以回传该资产的原始提示词，但那是资料库里已有的字段。
- 不实现图像生成：Agent 能看图，不能产图。
- 不做跨图比对、相似度或一致性评分；是否一致由模型依据画面自行判断。

## 影响范围

- `ai-tools.mjs`、`ai-agent.mjs`、`server.mjs`、`dist/app.js`
- `tests/agent-tools.test.mjs`、`tests/agent-loop.test.mjs`、`tests/subpath-routing.test.mjs`

## 未解决问题

- 附图上限 4 张与单次请求张数是代码常量，未在设置界面暴露。
- 同一张图在后续轮次会被重复上传（会话里保留），未做去重或压缩。
- Agent 是否需要按用途（人物 / 环境 / 物品）批量浏览，还是保持按编号精确取图。
- 卡牌草案与模拟状态的边界是作者当前的决定；若将来放开，需要另立契约。
