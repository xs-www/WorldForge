# ADR-0019：世界观模块改为「世界列表 → 世界内资料」两级结构

- 状态：canon（技术边界）
- 日期：2026-10-15
- 决策者：作者
- 来源：作者要求世界观架构点进去先只有世界面板，进入某个世界后才显示该世界的其余设定

## 背景

世界观模块此前进入即显示 13 类资料的平铺标签页，`renderLoreList()` 只按类型过滤，所有世界的资料混在同一份列表里；关联下拉列出全部世界的条目。作者无法从界面区分「这是 W01 的势力」还是别的世界的势力，也无法在不被其他世界资料干扰的情况下专注于一个世界。

资料层本来就有 `worldId` 字段（`normalizeLore()` 默认 `W01`），所以本次不需要改数据模型，只需把「先选世界」提升为界面的一级结构，并让过滤贯穿所有视图。

## 决策

1. 世界观模块分为两级：一级是 `#worldHub` 世界面板列表，二级是 `#worldDetail` 单个世界的资料工作区。进入模块或从其他模块切回时回到一级。
2. 一级面板由 `WorldforgeWorldScope.groups()` 生成，来源是「世界条目 ∪ 数据中出现过的 `worldId`」的并集。只有 `worldId` 而没有对应世界条目的资料显示为 `unassigned` 面板，不会被隐藏，并可在该面板上归入某个已存在的世界。
3. 进入某个世界后，`renderLoreList()` 只渲染 `worldId` 等于当前世界的资料；标签页计数、地理树、编年史树同样只看到当前世界。
4. 二级仍保留全部 13 类标签页，包含「世界」本身，因此可以在世界内部就地编辑该世界的名称、概述与正文。
5. 编辑器里的「所属世界」由自由文本输入改为只读展示（`#loreWorldIdText`）；`collectLoreForm()` 使用当前世界而不是表单字段。跨世界搬运通过一级面板的归入操作完成。
6. 关联资料下拉按世界分组：当前世界的条目平铺在前，其他世界的条目放进「其他世界（跨世界引用）」分组，保留跨世界引用能力但明确区分。
7. 一级面板显示每个世界的状态、事实层次、各类型计数与资料总数；一级搜索按世界名称、编号、摘要与正文匹配。
8. 新增「新建世界」：`nextWorldId()` 取最小未占用的两位编号（`W01`、`W02`…），并同时写入世界条目的 `id` 与 `worldId`。已被资料引用但还没有世界条目的编号也算占用，避免撞号。
9. 新建资料、新建故事、新建地理条目、新建编年史条目都继承当前世界。

## 边界

- 不改变数据模型、SQLite Schema、导出结构或既有条目 ID；`worldId` 语义不变。
- 世界内部不提供「把这条资料改到另一个世界」的操作（作者选择）。跨世界搬运只在一级的未归属面板上提供。
- 一级面板不提供删除世界的入口；删除仍走条目编辑器的既有删除逻辑。
- 不实现世界之间的复制、模板或派生。

## 影响范围

- `dist/world-scope.js`（新增）、`dist/app.js`、`dist/index.html`、`dist/styles.css`
- `tests/world-scope.test.mjs`（新增）、`tests/subpath-routing.test.mjs`
- `package.json`

## 未解决问题

- 在两个都已存在的世界之间搬运单条资料目前没有界面入口。
- 删除世界条目会让其资料变成未归属面板，是否需要「删除世界时一并处理资料」的确认流程。
- 一级是否需要跨世界全文搜索（当前只搜索世界本身）。

## 修订

- 2026-10-15：决策 6 描述的「关联下拉按世界分组」已被可过滤的分栏选择窗口取代，见 [ADR-0020](ADR-0020-filtered-relation-picker.md)。同世界优先、跨世界可选的分层意图保持不变，只是从下拉分组改为选择窗口内的世界过滤器。
