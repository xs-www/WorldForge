# WorldForge 实际使用流程测试报告（2026-10-17）

> 结论先行：按「新建世界 → 建资料 → 编辑 → 删除 → 出卡 → 管关键词/美术 → 备份」的真实使用顺序驱动界面，共确认 **15 项缺陷**，其中 **3 项阻断级**。用户反馈的「部分内容无法删改，如世界」可直接对应到缺陷 D1、D2、D3；另有一批「只能新建、不能修改/删除」的模块缺口（卡牌、关键词、美术资产、导入恢复）。本报告只做测试与建议，**未修改任何实现代码**。

## 1. 测试目标

1. 按实际使用流程逐模块走一遍，确认当前交互是否成立；
2. 找出「无法删改」的具体环节、触发条件与根因；
3. 对照 README 已声明能力，标出**已声明但实际缺失**的功能模块；
4. 给出可执行的修改意见（按优先级与实施顺序）。

## 3. 缺陷清单

严重度：**P0** 阻断正常流程 / **P1** 功能缺失或数据被破坏 / **P2** 体验与一致性。

### D1（P0）基线世界 W01 在未保存过的库里无法打开编辑

- **复现**：全新库 → 进入 W01 → 在「世界」分类点世界条目；或直接 `loadLore('W01')`。
- **现象**：编辑器停留在「新建世界」，名称、概述、ID 全空；控制台抛
  `TypeError: Cannot read properties of undefined (reading 'kind') at loadLore (app.js:79)`。
- **证据**：
  - 种子条目的字段为 `id,type,name,status,truthScope,worldId,summary,details,constraints,openQuestions,tags,relationIds,attributes,location,updatedAt,seeded` —— **没有 `chronicle`**；
  - `normalizeLore()` 的输出字段包含 `chronicle`；
  - `loadLore()` 里 `chronicleKind: e.chronicle.kind || 'chronicle'` 正是抛错点。
- **根因**：`dist/app.js:39` 的 `readLore()` 把 `W01_SEED` 直接前置返回，**未经过 `normalizeLore`**：
  ```js
  return entries.some(e=>e.id==='W01') ? entries : [W01_SEED, ...entries];
  ```
  而 `W01_SEED`（`dist/app.js:13`）是手写常量，缺少后来新增的 `chronicle` 字段。
- **影响**：世界的基础信息改不了；用户若在「新建世界」状态下继续填名字并保存，会**新增一条同 worldId 的重复世界条目**（实测产生 `W-DRAFT-MVBTE9H8 / 魔导工业世界X / worldId=W01`），而世界面板标题仍是旧名字 —— 使用者看到的就是「改了没反应」。
- **建议**：`readLore()` 统一归一化，一行修复：
  ```js
  return (entries.some(e=>e.id==='W01') ? entries : [W01_SEED, ...entries]).map(normalizeLore);
  ```
  同时给 `W01_SEED` 补 `chronicle:{kind:'',parentId:'',dateLabel:'',order:null}`，并补一条回归测试（种子条目字段集合须与 `normalizeLore` 输出一致）。

### D2（P0）W01 的「删除」按钮可见但点击完全无反应

- **复现**：真实数据副本 → 进入 W01 → 「世界」分类点世界条目 → 点「删除」。
- **现象**：按钮可见（`hidden=false`），点击后条目仍在、无确认框、无 toast、编辑器状态不变。
- **证据**：点击前后 `readLore()` 都能查到 `W01`，`__toasts` 为空数组。
- **根因**：`deleteLore()`（`dist/app.js:82`）第一行 `if(!activeLoreId||activeLoreId==='W01')return;` —— **静默 return**；而按钮显隐只依据 `e.seeded`（`dist/app.js:79`）。作者库里的 W01 是自己保存过的条目（`seeded=false`），所以按钮显示，但特例直接吞掉点击。
- **影响**：世界「删不掉」且没有任何解释，用户无法区分「受保护」与「坏了」。
- **建议**：把静默 return 改为显式反馈（`showToast('基线世界 W01 不可删除；如需新世界请新建')`），或在 UI 上按 `id==='W01'` 隐藏按钮并给出 title 说明。二者必须与实际行为一致。

### D3（P0）删除世界后世界仍留在世界面板（子资料变成「未归属」分组）

- **复现**：新建世界 W02 → 在 W02 下建 1 条势力 → 进入 W02 →「世界」分类选中世界条目 → 删除。
- **现象**：世界面板仍显示一个 `未命名世界（W02）` 卡片，标注「未归属 · 这些资料引用了不存在的世界条目」，其下资料 `worldId` 仍是 `W02`。
- **证据**：
  - 删除后 `worldGroups()` = `[{W01…}, {worldId:'W02', assigned:false, total:1, entries:['faction:FAC-…']}]`；
  - 面板文案：「未命名世界（W02）未归属 … 势力 1 / 查看 1 条资料 / 归入」。
- **根因**：世界分组由资料派生（`dist/world-scope.js:20` `groups()`）；`deleteLore()` 只删世界条目，不处理其下资料，也不提示会遗留孤儿；删除确认文案只有「删除本地草案”X“？此操作无法撤销。」。
- **影响**：删除世界看起来「没删掉」；残留的孤儿资料只能逐条删除，或用面板上的「归入」把**整组**搬到别的世界。
- **建议**：世界删除要有明确语义（三选一，需作者裁定）：
  1. **级联删除**：二次确认时列出「该世界下还有 N 条资料」，确认后一并删除；
  2. **保留并归入**：删除前要求选择目标世界，把子资料 `worldId` 迁移过去；
  3. **拒绝删除**：只要还有子资料就不允许删除，提示先清空或迁移。
  无论哪种，删除后都不应再出现「未命名世界（XX）」空壳分组。

### D4（P1）世界稳定 ID 改名不级联，世界被拆成两半

- **复现**：新建世界 W03 并在其中建 1 条角色 → 打开世界条目 → 把稳定 ID 从 `W03` 改成 `W09` → 保存 → 进入 W09。
- **现象**：
  - 世界条目变成 `id=W09, worldId=W03`；
  - `enterWorld('W09')` 显示「未命名世界（W09）」「W09 · 没有对应的世界条目」，分类列表为空；
  - 原 `W03` 分组仍然存在，且其 `entries` 里含 `world:W09`、角色也仍在 W03。
- **根因**：`collectLoreForm()`（`dist/app.js:80`）里 `worldId: currentWorldId()` 恒取当前世界，`saveLore()` 不检测「世界条目 ID 变化 → 同步子资料/卡牌/偏好」。
- **影响**：一次改名即可让一个世界的身份与环境脱节，且无法通过 UI 修复（`collectLoreForm` 永远把 worldId 写成当前世界）。
- **建议**：二选一，且必须在保存前拦截：
  - **禁止改世界 ID**：世界条目的 ID 输入框只读，改名只允许改「名称/概述」；
  - **级联改名**：ID 变化时同步所有 `worldId===旧ID` 的资料、`card.worldId`、`readPreferences().worldId`，并在确认框里写明影响条目数。

### D5（P1）卡牌无法删除（也无复制/归档）

- **证据**：卡牌编辑器按钮全集（真实 7 张卡的环境）为 `newKeyword / backToCardLibrary / saveCard / openCardLoreRefPicker / resetCardCrop / optimizeCardArtPrompt / clearCardArt / generateCardArt` 与关键词快捷 chip；卡牌库操作区无「删除/移除/复制」；`typeof deleteCard === 'undefined'`，`app.js` 中不存在任何卡牌删除函数。
- **影响**：草案越积越多（当前 7 张），无法清理；误建、错建卡永久留存；卡牌库的搜索/筛选只能绕过。
- **建议**：在编辑器标题栏加「删除卡牌」（二次确认 + 清 `cardPngCache` + 清理 `loreRefs` 反查），卡牌库卡片上加「⋯」菜单（复制副本 / 删除）。

### D6（P1）关键词只能新建，不能编辑或删除

- **证据**：关键词面板操作只有「定义关键词」；对话框标题固定「新建关键词」，字段只有 `keywordName / keywordDefinition`，按钮只有 `取消 / 保存关键词`；关键词条目本身是选择用 `<button>`；无 `deleteKeyword/editKeyword`。真实库 9 个关键词（战吼、法术迸发、冲锋、圣盾、剧毒、亡语、进击、嘲讽、发现）全部无法改。
- **影响**：关键词定义一旦写错（错别字、规则变化）无法修正，只能新增一条近似重复项，卡牌上的引用也无法迁移。
- **建议**：关键词条目增加「编辑 / 删除」；删除时列出引用它的卡牌，提供「改为引用其他关键词 / 仅从卡牌移除」两种处理；编辑时保持 `id` 不变（ID 是卡牌引用的外键）。

### D7（P1）美术资产无法真正删除

- **证据**：`DELETE /api/art-assets/<id>` → **405**（服务端只注册了 `GET …/file`、`POST …/unbind`，见 `server.mjs:506-517`）；解除绑定后资产仍计入素材库（13 → 13），磁盘文件保留。既有 TODO 也已登记此事。
- **影响**：素材库只增不减；误传/不满意的候选图永久占用空间并污染「未使用原画」列表。
- **建议**：新增 `DELETE /api/art-assets/:id`：删除 DB 行 + 磁盘文件，并同步清理引用它的 `card.artAssetId`、设定视觉原型绑定、`cardReferenceAssetIds/loreReferenceAssetIds`；对「已绑定到卡牌」的资产要求先解绑或给出显式级联确认。

### D8（P1）没有导入 / 恢复 / 备份，导出也不含图片

- **证据**：设置 → 数据管理只有 `settingsExport:导出完整 JSON`；无 `settingsImport/settingsReset/settingsBackup`。`exportData` 的 payload 为 `{project,schemaVersion,exportedAt,loreEntries,notes,keywords,cardDrafts,artAssets}` —— 只有元数据，**没有图片文件**，也没有任何回灌入口。
- **影响**：README 建议「长期归档使用完整 JSON 导出」，但导出无法还原成一个可用的库；换机、库损坏、误删后没有恢复路径。
- **建议**：桌面级导入/导出闭环：
  - `导出` 增加「包含图片（zip：`data.json` + `assets/`）」，或 `data.json` 内联 data URL；
  - `导入` 做 schema 校验 + 冲突策略（覆盖 / 合并 / 另存为新 ID），导入前自动落一份快照；
  - 增加「本库快照/恢复」（服务端定时 VACUUM INTO 或复制 `.sqlite`）。

### D9（P1）单条资料不能跨世界移动

- **证据**：编辑器里的「所属世界」是只读 `SPAN#loreWorldIdText`；编辑面板内匹配 `world` 的输入控件数量 = 0；`collectLoreForm` 恒用 `currentWorldId()`；不存在 `moveLoreToWorld/reassignLore` 之类函数。唯一的迁移手段是世界面板上「未归属组 → 归入」的**整组**迁移。
- **影响**：资料建错世界后只能删掉重建；多世界创作时无法整理归档。
- **建议**：把「所属世界」改为可编辑下拉（列出已存在世界 + 当前世界），保存时写 `worldId`；卡牌编辑器的「世界」字段同样处理；移动时同步地理父级/编年史父级的合法性校验（不合法则给出明确提示）。

### D10（P2）删除资料不清理卡牌的 `loreRefs`，且 UI 不提示失效引用

- **证据**：从资料生成卡牌草案（`loreRefs:['ITM-…']`）→ 删除该资料 → 卡牌仍保留 `loreRefs:['ITM-…']`；卡牌库文案不含「缺失/失效/不存在」。
- **影响**：卡牌「设定来源」出现悬空引用，无法从 UI 察觉或修复（只能解绑——但解绑需要打开源条目，而源条目已删除）。
- **建议**：`deleteLore()` 同时清理各卡牌的 `loreRefs`；若选择保留，则在卡牌编辑器把缺失项红字标出并提供「移除失效引用」。

### D11（P2）「备注 / 决策记录」功能不可达（死代码）

- **证据**：`index.html` 存在 `#noteDialog / #noteText / #saveNote`，`app.js` 有 `#saveNote` 的保存逻辑；但**没有任何按钮/入口打开这个对话框**，`app.js` 里也不存在静态文档所称的 `openNote(key)` 函数（静态文档已漂移）。服务端 `notes` 表里有 1 条历史数据。
- **影响**：一条已建成的功能用户永远打不开；同时静态文档仍在描述它。
- **建议**：二选一——补回入口（如世界详情页/资料页的「决策备注」按钮，按 `noteKey` 打开）；或删除对话框与遗留绑定，并在静态文档里改记为已移除。

### D12（P2）世界面板上的分类计数显示 0 / 返回后变陈旧

- **证据**：真实数据副本的世界面板显示「1 个世界 · 20 条资料」，但 13 个分类页签的计数全是 `0`；在隔离库里手动调用 `renderLoreList()` 后计数才变成 `world:3 / location:4 / faction:1 …`（非空库的正常值）；进入某个世界后计数变成该世界的数字，返回世界面板后**仍显示上一个世界的数字**（实测 `insideWorld` 与 `afterLeave` 完全一致）。
- **根因**：计数只在 `renderLoreList()`（`dist/app.js:95`）里刷新，而 `leaveWorld()`/`renderWorldHub()` 不调用它；`activeWorldId` 为空时页签仍显示旧世界数据。
- **建议**：`renderWorldHub()` 末尾以「全部世界」作用域刷新计数，或把计数渲染抽成独立函数 `renderLoreTypeCounts(scope)` 供两处复用。

### D13（P2）地理层级强制逐级，城市/地点无法直接挂到大陆

- **证据**：`parentKinds`（`dist/geography.js:11-19`）规定 city/site/route 的合法上级只有 `country/region/area/city`，**不含 continent**。真实库里「安地斯城（蓄魔阶梯城）」「高原勘验院试所」两条 `parentId` 为空，落在「待整理的地理条目」；打开后上级下拉只有「请选择所属上级」一项，保存被拒（toast：`请选择符合层级且属于同一世界的上级`，帮助文案：`请先建立可作为上级的地理条目`）。
- **影响**：作者只有大陆级框架时，城市永远挂不上去；「待整理」面板提供的修复入口在这种情况下同样不可用。
- **建议**：
  - 允许「跨级挂载」（city 可直接挂 continent，或提供「跳过中间层级」开关）；
  - 或在「待整理」条目上提供「改为可归位类型」的一键操作；
  - 或把「＋地区/＋城市」直接放进地理树的节点菜单，保证从父级入口进入时上级已预填（当前 `＋国家` 入口工作正常，可作范式）。

### D14（P2）AI preset 选择器与卡牌文字 Agent 仍未实现

> 2026-10-17 状态更新：Sprint 3 已交付分入口 preset 选择器（设置页「Agent 模式」、`agent-settings.json`、自由对话快照与切换确认），Sprint 4 已交付卡牌文字 Agent（`POST /api/ai/card` + 卡牌编辑器面板）。本条保留原始测试记录；本轮之后是否关闭需复审在浏览器中重新走一遍这三条路径。

- **证据**：设置面板导航只有「语言模型 / 提示词工程 / 图像生成 / 编辑偏好 / 数据管理」，无 preset 选择；后端已提供 `GET /api/ai/presets` 与响应回显 `agent` 快照。与 README 第 13 行、`todo.md` Sprint 3–4 的声明一致。
- **影响**：三个入口固定使用服务端默认 `lore-writer` / `free-creator`，作者无法切换；卡牌文字设计没有 Agent 入口。
- **建议**：按既定 Sprint 3–4 计划实施即可，本项属「已声明未实现」，不算回归。

### D15（P2）历史数据里的 `chronicle.kind` 污染与派生 ID 前缀不一致

- **证据**：真实库 9 条编年史条目的持久化 `chronicle.kind` 全为 `'continent'`（旧版本字段复用遗留）；读入时被 `chronicle.js` 归一化为 `chronicle/entry`，所以界面显示正常，但**库里存的是非法枚举值**，任何直接读库的工具都会误判。另：`createWorld()` 使用 `makeLoreId('world')` 生成 `W-DRAFT-…` 形式的 ID，与世界 `W##` 约定不一致（D1 的重复条目就是这种 ID）。
- **建议**：一次性数据迁移把非法 `chronicle.kind` 归一化并写回；`makeLoreId` 对 world 类型改用 `nextWorldId()`（或直接禁止手动改世界 ID，见 D4）。

### 架构层面的一条建议

当前内容写入是「前端整库快照 → `PUT /api/content` → 服务端乐观锁（`expectedRevision`）」（`server.mjs:501-505`）。在单用户、少量数据下没问题，但上述删除/移动类操作会越来越依赖前端全量重写，容易产生「删了一半」的状态（D3 就是典型）。建议后续为**世界、卡牌、关键词、美术资产**补最小写接口（`POST /api/worlds/:id/delete`、`PATCH /api/cards/:id` 等），把「一个操作」变成一个事务，服务端负责级联与引用清理，前端只做展示刷新。
